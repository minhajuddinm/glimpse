# Decisions

One line per deviation from BRIEF v2, with the reason.

| Date | Area | Decision | Rationale |
|---|---|---|---|
| 2026-11-18 | Platform | Windows 10 2004+ / Windows 11 only for now; macOS code paths deferred. | Owner's call: ship and verify on the machine we can test on. |
| 2026-11-18 | Storage | `node:sqlite` (built into Electron 45 / Node 24) instead of `better-sqlite3`. | better-sqlite3 has no prebuilt binary for Electron 45 and building needs Visual Studio; node:sqlite needs no native build and was verified in Electron 45 with FTS5 (SQLite 3.54.1). |
| 2026-11-18 | Stack | React 18.3 kept per brief; TypeScript pinned to 5.9.3. | typescript-eslint 8.73 supports TypeScript < 6.1. |
| 2026-11-18 | Build | electron-vite 6 on Vite 8 (Rolldown); configs are `.mts`. | Current stable toolchain; ESM configs avoid Vite's CommonJS loader warning. |
| 2026-11-18 | ASR | Local sherpa-onnx streaming ASR is primary; Groq Whisper is optional, and only for re-transcribing trigger utterances. whisper.cpp and the 1.5s-overlap/LCS de-duplication step are dropped. | Owner wants free + fast. Groq's free tier allows 20 req/min, but 1.5s chunks for two sources need ~80. A streaming recogniser produces no overlapping chunks to de-duplicate. |
| 2026-11-18 | LLM | Claude Haiku 5.5 primary (thinking disabled for answers); Groq `gpt-oss-120b` free fallback; Claude Sonnet 5.5 for "elaborate". | Fast time to first token and good accuracy at ~$0.0004/answer; a zero-cost path when no Anthropic key is set. |
| 2026-11-18 | Loopback | Electron's built-in `setDisplayMediaRequestHandler({ audio: 'loopback' })` instead of `naudiodon`. | naudiodon is unmaintained; the built-in path needs no native addon. Trade-off: it captures the default output device only. |
| 2026-11-18 | Answers | New: notes-folder retrieval (FTS5 + local embeddings), searched before every answer. | Owner requirement: answers come first from their own interview notes and prepared answers. |
| 2026-11-18 | Capture hiding | Glimpse sets the display affinity itself with koffi before the overlay is shown, reads it back, and hides the overlay again if Windows reports it capturable (fail closed). | Measured on Windows 11 build 26300: Electron applies `WDA_EXCLUDEFROMCAPTURE` only when a window is shown and clears it on hide, which leaves a possible one-frame gap. |
| 2026-11-18 | Hotkeys | Default show/hide is `Ctrl+Alt+G`, not `Ctrl+Alt+Space`. A registration failure raises a notification and is flagged in Settings. | `Ctrl+Alt+Space` is Claude Desktop's Quick Entry shortcut: the first e2e run lost the key to it and the failure was silent. |
| 2026-11-18 | Click-through | Whole panel passes mouse events through while click-through is on; only the header controls are a hit-box, polled every 60 ms. | The brief's "re-enable events only inside the panel hit-box" needs a hit-box smaller than the panel, otherwise click-through on could never let a click reach the app behind (gate G3). |
| 2026-11-18 | Self-test | Adds a baseline capture (overlay hidden) and a positive control (protection briefly off); PASS needs both. Diff images are shown but never persisted. | A bare "no canary pixels" result also passes if the overlay is off-screen; wallpaper can be magenta/green; the images are screenshots of the user's screen. |
| 2026-11-18 | Win10 < 2004 | Capture-safe mode (alpha 0.15) is shown as a status badge in Settings, not as a one-time dialog. Not tested: no such machine. | Keeps the first pillar free of modal dialogs; behaviour implemented from the brief. |
| 2026-11-18 | Panic | `PanicController.captureMuted` and `onCaptureMuted()` are the hook Pillar B must honour; nothing is captured yet, so nothing is muted yet. | Audio capture does not exist until Pillar B. |
| 2026-11-18 | macOS-only calls | `setVisibleOnAllWorkspaces`, `app.dock.hide()` and the NSWindow shim are omitted. | Windows-only scope; they are no-ops or absent on Windows. |
| 2026-11-18 | Dev flags | `--selftest` and `--canary=<seconds>` run headless against a throwaway profile. | Lets the capture claim be verified without a UI and from CI-less machines. |
| 2026-11-18 | Live test | Two steps: a 5 s control with protection OFF, then the protected pattern. `stop()` always re-protects before clearing the pattern, and panic stops any live test. | A first live test on the owner's PC showed nothing on their own screen. A bare "pattern not seen" cannot be told apart from "this viewer cannot see the screen at all". |
| 2026-11-18 | Remote viewing | Capture-test tab warns when Parsec, Sunshine, AnyDesk, TeamViewer, RustDesk, Chrome Remote Desktop, VNC, Splashtop or an RDP session is detected. | The owner's PC runs Parsec and Sunshine with virtual displays. Streaming captures the screen like a recorder, so a protected overlay is invisible to a remote viewer too. This is inherent to capture exclusion, not a bug. |
| 2026-11-18 | Self-test | The Run button needs a "not sharing right now" confirmation. | The control capture briefly un-protects the overlay, and the owner ran it during a Meet share, where the pattern flashed. |
| 2026-11-18 | Live card | The card derives "running" from the session's end time as well as from events, resyncs with `live:get` on mount and window focus, and applies the response of start/control/stop. `LiveSession.stop()` always reports its status and hides the overlay if protection cannot be restored. The `mode` field defaults to null on the wire. | The owner's card stuck on "0s" with every button disabled: the "ended" event had been dropped (a renderer newer than the running main process), and nothing else could clear it. |
| 2026-11-18 | ASR model (M-B0) | **Kroko English streaming Zipformer (`kroko-en`, 55 MB) is the default**, fed 250 ms pre-roll, a 400 ms real-time hangover and 600 ms of instant tail padding. Nemotron 0.6B (447 MB) stays available as an optional "high accuracy" model. Measured on this PC (i7-14700HX, 2 threads, sherpa-onnx 2.0.1, 24 synthetic utterances plus 3 real recordings): Kroko 0.5% WER clean / 1.4% at 15 dB SNR, voice-to-text p95 about 550 ms; Nemotron 0.5% / 1.4%, about 874 ms; NeMo FastConformer 480 ms 3.7% / 3.7%, 629 ms; NeMo 80 ms 1.8% / 3.2%, 846 ms; Zipformer 2023-06-26 5.9% / 8.2%, 597 ms; Zipformer 20M 54% (unusable). On the 3 real recordings (77 words, one at 8 kHz) every model was effectively perfect; the only differences were spelling variants (dishonoured/dishonored) and a name. | Kroko matches the most accurate model at a fraction of the size and latency, and leaves the 1.2 s voice-to-transcript budget (G6) about 650 ms of headroom. Caveats: the test speech is synthetic and the CPU is fast, and 77 real words cannot separate close models, so G6 must still be confirmed on a real two-person recording. Tail padding below 400 ms truncates final words (0 ms gave 4.6% WER, 200 ms gave 2.3%). |
| 2026-11-18 | WER scoring | `normalizeForWer` treats digits, `$`, `%`, punctuation, case, spelled-out acronyms ("a p i" = "api") and compounds as equal before counting errors. | The first benchmark run scored Nemotron's "$45,000" and "23%" and the TTS's "a p i" as errors; it also showed that the test audio needed a pre-roll and tail padding like the live pipeline. |
| 2026-11-18 | Pillar B: end of speech | Silero VAD (sherpa-onnx, 0.4 s hangover) decides when someone stopped talking; the recogniser's own endpoint is only a 1.2 s fallback and its "nothing heard for N s" rule is disabled. Each finished utterance gets 1.2 s of instant zero padding. | Measured: the recogniser's endpoint alone gave p95 2.5 s (fails G6). Live testing also caught its no-speech rule firing just as the next sentence began, splitting it in two; the continuous-call benchmark now checks for split sentences. Kroko needs about 1.5 s of trailing context in total or it drops the last word. |
| 2026-11-18 | Pillar B: G6 | `npm run bench:pipeline` (one recogniser, 24 sentences, 3 s gaps, like a call): p95 543 ms, 0 split sentences, 0.5% WER. Live on this PC through real speakers and loopback: p50 501 ms, p95 525 ms. | Synthetic speech; still to confirm with a real two-person recording. |
| 2026-11-18 | Pillar B: capture | A hidden capture page records loopback (Electron `getDisplayMedia` + `audio: 'loopback'`) and the mic (`getUserMedia`, AEC/NS/AGC on), resamples both to 16 kHz in an AudioWorklet and streams 100 ms chunks. Microphone and system-audio permission is granted only to that page. Recognition runs in a `utilityProcess` restarted with backoff, with a circuit breaker after 5 failures. | Keeps audio work off the main thread; a model crash cannot take the app down; no other window can open the mic. |
| 2026-11-18 | Pillar B: echo | Text-level echo guard: a "you" line that matches a "them" line or partial from the last 4 s (word Jaccard ≥ 0.6, ≥ 3 words) is dropped. Envelope cross-correlation from the brief is not implemented. | Live test through speakers produced no echoed "you" lines; revisit if a real call shows leaks. |
| 2026-11-18 | Companion page | Off by default. A local HTTP server (port 47823, falls back to a free port) serves an empty page; data needs a random 24-character code in the URL, compared in constant time, with lock-out after 20 wrong codes a minute per address. "Allow other devices" switches from 127.0.0.1 to all interfaces (LAN and Tailscale). Live updates use server-sent events. | The owner views the PC through Moonlight, where the overlay is invisible by design; the companion page shows the transcript (and later the answers) on a second device. |
| 2026-11-18 | Settings window | Not protected from capture. Closing it keeps Glimpse running in the tray, with a one-time notification saying so. | Owner's decision. |
| 2026-11-18 | Diagnostics | `GLIMPSE_AUDIO_DUMP=<folder>` records exactly what the speech worker receives; `node scripts/replay-dump.mts <folder>` replays it with a per-chunk VAD and text trace. | This is how the split-sentence bug was found. |
