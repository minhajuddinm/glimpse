## Pillar C — answers and notes
- **Notes folder at the app base** (`<app>/notes`, or next to `Glimpse.exe` when packaged), as the user asked. "Add files…" copies files there; the folder is watched and git-ignored. Not a user-picked folder list as originally planned.
- **Hybrid ranking = cosine similarity + small keyword bonus**, not reciprocal rank fusion: RRF let a shared keyword outvote meaning (G11 4/5 → 5/5). Instant prepared-answer threshold calibrated to 0.57 on bge-small (plan said 0.85, which no paraphrase reached).
- **node:sqlite FTS5** instead of better-sqlite3 (no native build tools on this machine); `fs.watch` recursive instead of chokidar.
- **Keys**: `safeStorage` async API (DPAPI); decrypted keys held in main memory only, never sent to a renderer.
- **Sonnet "elaborate"** uses the server-side fallback beta so a classifier decline still returns an answer.
- **Groq is text-only**: screenshot questions need the Anthropic key.
- **Installed app keeps notes in `Documents\Glimpse Notes`** (dev keeps `<app>/notes`): the install folder can be read-only and is wiped on uninstall/update. The embedding model ships via `extraResources` and loads from `process.resourcesPath`.
- **Speech engine idles**: the voice detector now gates decoding (600 ms pre-roll keeps the first word), and decoding uses 1 thread instead of 2 (same p95 543 ms and WER 0.9% in `bench:pipeline`, 2.5× less CPU; ONNX Runtime's worker threads spin between runs). Installed app idle CPU went from ~160% to ~9% of one core.
- **Notes relevance cutoff 0.55**: passages below this similarity are neither sent to the model nor cited (unrelated questions peaked at 0.50, rewordings start at 0.61). `bench:kb` now also asserts that unrelated questions cite no notes.
- **Data stays on the install drive**: when Glimpse is installed (or run from source) on a non-system drive, the Electron profile moves next to it (`<parent>\Glimpse Data`, or `.glimpse-data/` from source) and the default notes folder is `<parent>\Glimpse Notes`. The first start copies `glimpse.db` and `Local State` (safeStorage's profile key) from `%APPDATA%\Glimpse`. The installer's auto-update copy in `%LOCALAPPDATA%\glimpse-updater` is removed after install (no auto-update yet). Build caches live in `.cache/`.
- **Notes folder is user-selectable** (Settings → Notes → Change folder…), never inside the install folder.
- **No GPU**: sherpa-onnx's npm build is CPU-only, and local compute is ~1% of the answer time (latency is the 0.4 s end-of-speech wait plus the cloud model). A CUDA build would add ~2 GB of runtime for no visible gain.
- **UI redesign** with the UI/UX Pro Max design system ("Modern Dark": layered glass surfaces, ambient glow, violet→indigo accent from the logo, Lucide SVG icons). Kept the brand violet instead of the suggested amber, and Segoe UI Variable (native on Windows 11, works offline) instead of a web font. Sidebar navigation with live listening status; accessible switches (role="switch"), visible focus rings, reduced-motion support.

## macOS port (started 2026-11-19, built in CI, not yet run on a Mac)
- **Same codebase, platform branches only where the OS differs**: capture hiding, data paths, the overlay window type, microphone permission and packaging. Everything else (speech, notes, answers, UI) is shared.
- **Capture hiding on macOS = `setContentProtection` (NSWindowSharingNone), with a known gap**: since macOS 15, apps that record through ScreenCaptureKit can still capture such windows, and Apple has no public API to prevent it. Glimpse reports the method as `sharing-none`, never claims "verified excluded", and asks the user to run the capture test with each app they use.
- **Overlay is a non-activating `panel`** visible on all Spaces and over full-screen apps, so it never takes focus (the macOS equivalent of `focusable: false` + `showInactive`).
- **Data in the standard per-user places on macOS** (`~/Library/Application Support/Glimpse`, `~/Documents/Glimpse Notes`): the "keep data on the install drive" rule is Windows-only, since /Applications is not writable.
- **System audio through Electron's loopback** (CoreAudio tap on macOS 14.2+, needs `NSAudioCaptureUsageDescription`); minimum macOS 13. The handler still passes a screen source, so macOS also asks for Screen Recording permission.
- **Ad-hoc signed, not notarized** (no paid Apple Developer ID): Apple silicon needs at least an ad-hoc signature to run. First launch needs right-click → Open, or `xattr -cr /Applications/Glimpse.app`.
- **One DMG per architecture, built on a matching runner** (`macos-15` arm64, `macos-15-intel` x64): the speech addon is installed per arch by npm. The workflow is manual or tag-triggered because macOS runner minutes count 10× on a private repo.
- **Shortcuts keep Ctrl+Alt on macOS** (Control+Option, shown as ⌃⌥): ⌘ combinations collide with app shortcuts. Users can rebind to ⌘ in Settings.

## Meetings and minutes (2026-11-20)
- **Transcript saved line by line to SQLite** (`meetings`, `meeting_lines`, migration 4) while a meeting runs, not held in memory: a crash or forced quit keeps it, and the next start marks it *interrupted* so minutes can still be written.
- **Minutes use the "deep" model** (Sonnet 5.5 with the server-side fallback, or gpt-oss on Groq): minutes are not latency-bound, and quality matters more than speed. Measured on a scripted 20-line sales call: Sonnet 5.2 s, Groq 1.2 s, both with all sections and key facts.
- **Markdown with fixed headings, not JSON**: works the same on both providers, renders directly, and is the file format saved to the notes folder. `cleanMinutes` strips fences/preambles and rejects output without a Summary.
- **Long meetings**: one request up to ~120K transcript tokens with Claude; with Groq (8K tokens/min on the free tier) the transcript is split into ~4.5K-token parts at line boundaries, minuted per part, then merged.
- **Only minutes go into the notes folder**, never transcripts: raw talk would crowd out prepared answers in notes search.
- **Meetings under 25 words** get no automatic minutes (mis-clicks, tests); "Write minutes" still works on them.
- **Listen mode**: "Only during meetings" pauses capture through the same path as panic hide (streams stopped, not just ignored), with its own message on the Audio page. Default stays "Always" so live answers keep working without a meeting.
- **No audio recording**: text only, for privacy and consent reasons. The app reminds users to tell others they are being transcribed.
- Known limit: a sentence still being spoken when you press Stop may be cut (its final text arrives after the meeting closed).

## Calendar (2026-11-20)
- **Secret iCal address instead of Google OAuth**: no Cloud project, no "unverified app" screen or 100-test-user limit. It works with Google, Outlook and iCloud. It's read-only, which is all briefs need. OAuth stays an option if write access is ever wanted.
- **The address is a secret**: stored with `safeStorage` like the API keys, write-only over IPC (the renderer only learns *connected*), never logged. Only https:// (webcal:// is rewritten); 20 s timeout, 10 MB cap.
- **ical.js 2.2.1** (Mozilla, no dependencies) for parsing: it handles RRULE/EXDATE/RECURRENCE-ID and the feed's VTIMEZONE definitions. Its types claim text properties are always strings and `RecurExpansion.next()` always returns a Time; both can be null, so they are read defensively (found by tests).
- **"Real meeting" = at least 2 attendees or a video-call link**, and not all-day. Only these get briefs.
- **Brief is a new answer kind** (`brief`, ≤ 90 words, Haiku): the prompt gets the invite in `<meeting>` instead of the live transcript, and notes are searched with the invite text.
- Sync failures keep the last good event list, so a dropped connection doesn't blank it.

## Recording the calls you join (2026-11-20)
- **Replaces calendar auto-recording**, at the user's request: a calendar meeting you don't join must not be recorded. The calendar now only names recordings and vouches for browser calls. The `calendarAutoStart` setting is gone (stored values are ignored); `autoRecordCalls` is off by default.
- **"Joined" = a call app has the microphone open**, read from Windows' CapabilityAccessManager record (`HKCU…ConsentStoremicrophone`, `LastUsedTimeStop = 0`). This is the record behind the taskbar's mic icon. `reg.exe query` takes about 30 ms, every 3 s, and only while the setting is on. No native hooks, no admin rights, and nothing about the call's content.
- **An allow-list of call apps** (Zoom, Teams, Webex, Slack, Skype, GoTo, RingCentral) plus browsers. Other mic users (OBS, games, dictation tools, Glimpse itself) are ignored. A browser holds the mic for many reasons, so it counts only when a window title shows a call (Meet, Teams, Zoom, Webex, Jitsi, Whereby) or a calendar meeting with a call link is on. Window titles come from `tasklist /v` for that browser only, checked at most every 10 s.
- **5 s to start, 20 s to stop**: a quick mic test is not a call, and a device switch or reconnect is not the end of one. A record left open by a crashed app is ignored when the app isn't running; this is checked before starting, and every minute while recording.
- Known limit: joining with "don't connect audio", or an app that closes the mic while you are muted, is not detected. Start the meeting by hand (`Ctrl+Alt+N`).
